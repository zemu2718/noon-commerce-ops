# 02 noon 运营工作台方案

## 1. 最终做成什么

**系统承担大部分标准化数字工作，人负责关键决策和异常：推荐选品，确认后准备素材与采购方案，再按授权采购、上架、投流，并持续检查经营结果。** 实物验货、仓储运输和复杂争议仍由人员或服务商处理，不承诺无人经营。

优先考虑**在 Octop 现有 Web 中增加业务页面**，交付一个统一的 noon 运营工作台，按需配浏览器插件和飞书提醒。运营使用同一地址完成业务，不另建一套重复 Web，也不开发独立桌面客户端。该方向仍需通过许可、固定版本构建和扩展验证。

这是拟议方案，不是采购、安装或生产操作授权。具体站点、履约模式、现用系统、权限和投入待确认；先用真实工作选一项试点，不预定销售报表或一次覆盖整个部门。

只看方案读本篇；比较候选、许可证及 GitHub 备用项目时，看 [工具调研参考](03-运营工作台工具调研参考.md)。当前建议来自文档及部分源码调研，尚未实测候选系统。

## 2. 每部分具体做什么

| 部分 | 具体功能 | 首期范围与边界 |
|---|---|---|
| **Web 主入口** | 今日待办、商品资料、任务进度、素材比较、审核、会话与结果查询；后续加入经营概览和选品对比 | 先做“今日工作＋商品／任务详情＋必要审核＋会话”，不先建空大屏 |
| **浏览器插件** | 在商品页选择资料并加入候选；关联 SKU 查看任务；在编辑页预览并辅助填写已审核内容 | 有页面操作瓶颈才做，先支持一个页面场景；不默认读取全部标签页、Cookie 或后台资料 |
| **飞书** | 重要异常、待审核和完成提醒；简短追问，链接回任务 | 复杂图片、采购与批量异常在 Web 处理；飞书批准须核验实际批准人及范围 |
| **Octop 候选底座** | 理解请求、管理会话、调用 Skills／MCP、解释结果，复用消息接入与简单定时触发 | 不充当经营账本；通用工具确认和 cron 不等于业务审批及可靠任务恢复 |
| **业务模块** | 保存商品事实、素材、任务和批准；计算成本、检查预算权限、防重复、核对执行结果 | 从第一项任务就需要；可与底座同机部署，不先拆微服务 |
| **ERP、API、文件处理** | 复用已授权的数据出口、刊登、库存订单和明确规则计算 | 先查 noon 与现成工具能做什么，有实质缺口才自研 |
| **浏览器自动化／RPA** | 无合适接口时，按固定流程导出、填表、上传并检查；必要时操作桌面软件。可以调研录制器，让运营先演示固定步骤，再由维护者审核为受控流程 | 不绕过验证码、风控或权限；录制回放不等于可靠生产流程，页面变化、登录失效、结果不明时停止，不让 Agent 随意操作生产后台 |

**页面扩展方式：** 在 Octop 内增加“今日工作、商品／任务详情、审核”等业务入口，复用现有会话，并按验证结果复用登录与消息能力；模型、Agent 和连接器管理仅向维护者开放。业务接口与任务记录单独划分模块，不修改 Harness 内核；业务权限仍由服务端校验，隐藏菜单不等于权限隔离。只有现有前端扩展或升级成本确实不可接受时，再评估独立 Web，不同时维护两套业务界面。

**插件是软件形态，RPA 是自动操作的方式，不是两套必装软件。** 插件可以仅显示侧栏，也可以执行固定步骤；RPA 还可操作桌面软件。流程文件或脚本只是操作指令，需要运行程序和执行环境。同一个浏览器助手可逐步增加自动操作，不必另建 RPA 平台。

插件、Web 和飞书共用同一任务与身份，不各建素材库或批准记录。浏览器关闭后，后台可继续已接受的生成等任务；依赖本地页面的步骤暂停等待。长期生产密钥不放插件或前端，页面内容也不能改变权限。

**暂不做桌面客户端：** 全天提醒、多人访问和共享任务仍需后台，桌面壳还增加打包与升级成本。只有主要任务是个人操作本地文件／软件时，再比较 DSH Desktop；个别本地步骤优先考虑轻量执行组件。

## 3. 工作怎样从建议走到执行

候选商品池 → 确认方向 → 找货源、核对规格与样品 → 确认报价交期、测算成本 → 批准采购 → 跟踪交货验收 → 批准上市方案 → 上架投放 → 看结果、补货或退出。

素材与采购准备可以并行，但最终图文视频必须来自已确认的销售商品和授权素材。图片相似不等于同款，估算销量不等于实际销量；不能把竞品参数直接当成自家商品事实。

| 决策点 | 人批准什么 | 系统在范围内继续做什么 |
|---|---|---|
| **产品方向** | 商品、市场、定位、资料及素材预算 | 整理货源和事实、准备询价，生成指定数量与风格的图文／视频草稿 |
| **采购方案** | 供应商、规格、数量、价格、交期和总额 | 发送获准采购单，跟进确认与交货；付款权限单独确认 |
| **上市方案** | 最终素材、刊登路径、售价范围、库存条件、渠道和投放预算 | 按新建商品或已有商品报价的实际路径提交，确认可售后按计划投放 |
| **经营例外** | 超范围、异常或需要改变方案的处理方式 | 暂停受影响步骤，提供依据和选项；取得新批准后继续 |

批准必须对应方案版本、对象和参数。流程稳定后，可设置有期限、可撤销的规则授权，不必每个机械步骤都询问；累计预算与次数由程序限制，不能拆任务绕过。一次选品确认不包含后续任意采购或投流。

## 4. 先用什么，暂不做什么

- **先比较 NOON ERP／瑞大师与现有系统。** 借鉴商品池、货源核查、两种刊登路径、算价、约仓和逐商品任务反馈；用同一任务演示正常与失败情况。未确认开放接口，不能默认可被工作台调用；不照搬会员、课程和 CMS。
- **优先验证 Octop，不直接定案。** 先处理内置办公 Skills 许可差异、固定版本构建及权限边界。它的 IM 身份、内存待批状态和任务恢复需要补业务约束；不通过则改用更简单入口，不强行套框架。
- **DSH 仅作本机备选。** 不同时深度二开两个底座，也不把局域网远控当部门共享后台。
- **Skills 按任务选。** 图片优先复用既有生成链路；视频先试授权实拍剪辑，需要时再生成补镜。选品查证据，英阿文案与素材要审核；不先安装大型 Skill 集合。
- **接入顺序：** 已授权接口／现成能力 → 文件导入导出 → 必要的固定页面自动化。noon FBPI 有官方路径，但目标账户、站点与专用仓条件需核实，不推断 FBN／FBP 所有功能都可接。

候选链接、版本、许可、竞品差异及 noon 开源备用线索集中在 [工具调研参考](03-运营工作台工具调研参考.md)，不是首期必装清单。

## 5. 按什么顺序交付

| 阶段 | 交付什么 | 通过后再继续 |
|---|---|---|
| **准备** | 跟岗缩小范围，取脱敏样例与正确结果；演示现成工具，核实许可、接口及底座 | 选定一项值得改的工作、最小投入上限和可用数据，不重做现成功能 |
| **首期：Web＋一个任务** | 资料输入、会话发起、进度、草稿审核、修改与结果保存；不开放生产写权限 | 全过程走通，刷新或会话断开不丢任务，费用及人工返工可追踪 |
| **第二期：补一个入口** | 页面复制填表是瓶颈就加轻插件；等待结果是瓶颈就加飞书通知 | 同一任务不重复录入；不误采资料、不发错人、不重复提醒 |
| **第三期：一种执行动作** | 采购单发送、上架或广告创建中选一种，按授权接入 | 批准、预算、防重复、结果核对及人工接手通过，不同时开放全部权限 |
| **后续：串起经营流程** | 一个站点、一种履约模式、熟悉类目和少量商品，衔接准备、执行与持续跟进 | 检查总工时与经营结果，再批准扩到更多商品、店铺和动作 |

首个任务可选：

- **素材制作：** 已确认 SKU 与授权实拍 → 套图或短视频草稿 → 检查 → Web 审核 → 修改并保存。图片、视频先选一个，明确生成数量、风格和费用上限，先不自动发布。
- **经营检查：** 已核对的库存或结算样例 → 规则检查 → 异常依据及建议 → 待办 → 人处理后记结果。先不自动采购、改价或回写库存。

不按岗位堆 Agent，也不以素材数量或图表数量验收；每新增能力都要减少实际工作，而不是增加审核负担。

## 6. 数据、任务和验收的底线

| 必须做到 | 具体要求 |
|---|---|
| **资料对应正确** | 用店铺、站点、仓库、模式及 SKU 对照关联；保留来源、币种、时区和更新时间。缺失、过期和零值分开，不承诺全部实时 |
| **任务可追查** | 保存输入版本、状态、费用、外部任务 ID 与结果。批量逐商品记录，部分失败不重跑成功项；取消和提交结果不明先标待核对 |
| **执行不重复** | 重复点击、消息重发、断线或重启不应再次下单或扣费。超时先查原任务，不能用模型“已完成”代替服务端结果 |
| **批准不能绕过** | 执行前重查批准人、对象、参数、额度、时效和业务状态；通用工具不能持有可绕过检查的同等生产写权限 |
| **数据和素材有边界** | 原始敏感资料和密钥放仓库外；模型、通知、日志和附件的外发权限分别确认。素材检查外观、规格、配件、字幕和阿语，去水印不等于授权 |
| **结果可验证** | 上架提交不等于可售，广告创建不等于投放；检查数据缺项、产品事实错误、越权、重复、重启和部分失败，变更后沿用原案例回归 |
| **收益算完整** | 比较操作＋审核＋返工＋维护总时间和全部费用，不只比生成速度。费用不全不称净利润，归因销售不等于增量；算法见 [经营目标和怎么算](../01-业务调研/02-经营目标和怎么算.md) |

安装、资料外发、付费试样、采购和生产操作分别批准。许可或权限不清、必须绕过平台限制、关键错误拦不住、重复执行无法控制，或投入超过预定上限时暂停。关闭工具不等于撤销已发生的业务操作，需核对影响并处理未完成任务。

## 7. 下一步确认什么

1. 站点、FBN／FBP／NGS 模式、现用 ERP 和协作工具，以及真实分工。
2. 哪项重复工作最值得先改，能否提供少量脱敏样例和正确结果。
3. 先供个人还是多人使用，是否需要关机后继续；页面操作是否确为瓶颈。
4. 可用的数据出口、账号权限及允许外发的资料范围。
5. 试验费用上限和可投入的维护时间；随后估算资料整理、接入开发、运行审核、升级及退出成本，不先承诺工期和收益。

后续选择、试用及结果接着更新本篇；工具证据只更新参考文件，不再分别新建阶段报告。实际采用的操作再写入岗位 SOP。
