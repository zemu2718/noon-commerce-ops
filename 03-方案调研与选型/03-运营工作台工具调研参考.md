# 03 运营工作台工具调研参考

[返回主方案](02-noon运营工作台方案.md)

本篇只在比较工具或准备试用时查阅。它记录公开资料初筛，不代表已安装、接入或验证；不要把“官网说支持”当成“公司账号能用”。查看日期：2026-09-23。

## 先记住这几个结论

1. **主产品方向：** 在 Octop 现有 Web 上增加运营页面，业务模块保存商品、任务、批准和结果；插件、飞书和 RPA 按需接入。
2. **noon 标准能力：** 订单、库存、目录和状态优先查 noon API、NOON ERP、瑞大师、Unicommerce、Omniful，不要先用 RPA 模拟已有接口。
3. **浏览器流程：** Playwright Codegen 最适合首个内部验证；Selenium IDE 可作运营录制对照；Browserflow／Writ 值得做商业演示候选。
4. **桌面／OCR：** 只有确实要操作 Windows、Excel、SAP 或 OCR，才看 Ui.Vision／OpenRPA／Power Automate／UiPath。
5. **所有录制流程都是草稿：** 运营录制 → 维护者审核 → 固定版本 → 批准后执行 → 保存逐步回执。录制文件不能直接获得生产写权限。

## 二、录制与 RPA

录制结果只能作为草稿，不能直接作为生产能力。采用前按四步处理：

1. **采集：**记录实际步骤、前置条件、输入、页面变化和期望结果。
2. **规范化：**去除凭据和敏感数据，改成参数，整理稳定定位、等待条件、异常分支和输出格式。
3. **封装：**固定运行环境、流程版本、权限、输入输出、回执和人工接管点。
4. **评测：**用正常、缺资料、无权限、超时、重复、部分成功、页面变化和人工接管案例回归。

只有步骤、参数、权限、成功判定和失败处理都能复核，才进入小范围试点；未通过时退回草稿或停止，不把“录制成功”写成“已接入”。

### 推荐顺序

| 候选 | 最适合什么 | 不足 |
|---|---|---|
| [Playwright Codegen](https://playwright.dev/docs/codegen) | 录制浏览器操作并生成可审查的 JS/TS；代码可进 Git | 不是 RPA 平台；需自建执行、凭据、审批、调度和回执 |
| [Selenium IDE](https://github.com/SeleniumHQ/selenium-ide) | 快速浏览器录制、回放和导出代码 | 生产治理需要自己补 |
| [Browserflow](https://browserflow.app/pricing) | 运营无代码录制、浏览器本地或云端定时；Starter 起有 API/Webhook | 凭据库、审批、审计、区域和留存未核实；有套餐和供应商锁定 |
| [Writ](https://usewrit.app/product/workflows/) | 录制、参数化、版本、REST/MCP、异步 task_id；最接近“录完可调用” | 价格、凭据、审批、状态枚举、取消和数据留存需演示 |
| [Ui.Vision](https://github.com/A9T9/RPA) | 浏览器＋桌面＋OCR／图像定位 | AGPL／商业授权、XModules、集中治理和回执需核 |
| [OpenRPA](https://github.com/open-rpa/openrpa) | Windows、SAP、Office 和桌面流程 | 部署较重；OpenFlow、凭据、审批和队列需实测 |
| Power Automate / UiPath | 企业审批、队列、审计、无人值守 | 订阅、实施和退出成本高；已有 Microsoft 环境才优先比较 |

这些候选不是同一类东西：Skill 是面向 Agent 的能力说明或调用封装；开源项目要单独核查许可证、依赖、维护和部署；商业产品要核查套餐、凭据、数据留存和退出；RPA 执行器负责实际页面或桌面操作；工作流编排器负责 API、文件、数据库、消息和 AI 服务之间的传递。n8n 属于最后一类，不是录制器。

以上是公开资料初筛，不是实测排名。GitHub 有仓库不等于许可证允许当前分发方式；Skill、开源项目和商业产品也都没有因此获得 noon 账户、站点、FBN/FBP/NGS 或卖家后台权限。许可证、版本、依赖和数据外发应在决定试用某一候选时固定核查。

**不优先：** TagUI（维护风险）、Robocorp Recorder（当前维护需补查）、Automa（适合浏览器原型但治理不足）。RPA 不绕过验证码、风控或权限。

### 与 Octop 怎么配

- **Octop：** 理解目标、选流程、传参数、会话和通知。
- **执行器：** Playwright、Ui.Vision、OpenRPA 或商业云工具，负责实际操作。
- **业务模块：** 批准人、店铺／SKU范围、预算、幂等、状态、截图／回执和失败恢复。

推荐链路：**运营录制 → 草稿 → 维护者审核和版本化 → 业务批准 → 执行 → 逐步回执 → Web／飞书展示。** HTTP、CLI 或 MCP 能调用，不等于已经完成身份、审批和防重复集成。

首个试点只做：读取商品价格／库存或导出报表。后续再做无副作用填表，最后才考虑改价、上架、采购和投流。

工具与业务分层的对应关系：Octop 负责理解目标、组织会话和传参；Skill 负责能力说明与调用约束；编排器负责等待、分支和通知；API、文件或 RPA 负责实际动作；业务模块负责批准、状态、幂等和结果核验；MCP 只提供连接，不代替这些职责。具体状态和恢复规则以[主方案](02-noon运营工作台方案.md#任务生命周期)为准。

## 三、RPA 与 n8n：不是一类工具

| 对比 | RPA | n8n 等工作流编排器 |
|---|---|---|
| 操作对象 | 浏览器页面、桌面软件、Excel、ERP 客户端 | API、数据库、文件、Webhook、消息和 AI 服务 |
| 操作方式 | 点击、输入、读取页面、截图、OCR、上传 | 请求接口、转换数据、条件分支、调用节点 |
| 适合没有 API 的后台 | 适合在授权范围内操作页面 | 不能直接代替页面操作 |
| 主要维护风险 | 选择器、浏览器版本、登录状态、页面改版 | API 版本、字段映射、凭据、节点和重试 |
| 运营录制 | 可以录制或生成页面流程 | 通常是拖拽节点或写表达式，不是录屏点击 |

### 在 noon 工作里的分工

**RPA：**打开后台、选择店铺、填写已审核商品资料、上传图片、提交并核对页面状态。

**n8n／其他编排器：**定时读数据或文件、做规则检查、调用 Octop 与生成服务、等待任务、发飞书消息、保存结果。

可以组合成：

```text
工作流或业务模块读取资料
→ Octop 分析并等待人工批准
→ RPA 在无 API 的页面上执行
→ 返回状态、截图和错误
→ 保存结果并通知飞书
```

n8n 不是当前必装组件。优先用 Octop、业务模块、文件／API 和受控浏览器执行；当流程变成“文件 → API → AI → 审批 → RPA → 飞书 → 数据库”，跨系统步骤明显增加时，再比较 n8n 或其他编排器。避免 Octop、n8n、RPA 各维护一套任务状态。

## 七、统一验证表

任何候选先用同一固定案例，不先接生产写权限：

1. 读取 10 个商品，输出 SKU、标题、价格、库存、图片和采集时间。
2. 生成 2 个上架草稿，只人工批准其中 1 个提交。
3. 读取 1 笔订单、同步 1 个库存变更，故意制造 1 个无效 SKU。
4. 失败、超时、重复运行、部分成功和浏览器关闭后，检查任务 ID、状态、错误、重试和是否重复操作。
5. 广告只做只读报表；未核实 Ads API 前，不改预算和投放状态。
6. 核实凭据不进录制文件和日志，数据区域、留存、删除、价格和退出方式。

**通过标准：** 能区分成功、失败、跳过、部分成功、待人工；能查询真实结果；不能绕过批准或重复扣费／改价。任何未核实能力标为“待演示”，不写成支持。

补充检查：是否有稳定任务 ID 和外部任务 ID；是否能查历史尝试和错误；超时或结果不明时是否先查原任务；暂停、恢复和浏览器重启后是否不会重复副作用；批量是否逐项保存结果；人工接管是否保留原因和已完成步骤；流程或能力版本变化后是否回归原案例。候选比较还要记录版本、维护边界、适用范围、停止条件和退出方式。

## 证据边界

本篇为公开资料初筛，未安装、构建、试用、购买或连接店铺。版本和价格以查看日期为准，部分页面没有完整日期或套餐口径存在差异；许可需要按实际分发方式逐项核实。更详细的源码证据已从主方案移出，后续只在决定试用某候选时补查。
