### 参考 NOON ERP 的业务功能，不照搬全部产品

2026-09-23 读取 [功能页](https://www.noonerpiu.com/capabilities.html)。下列是厂商页面声明及我们的拟议取舍，未验证上线范围、准确率、账户适用性或底层 API／RPA 实现；不直接作为开发承诺。

| 对方列出的功能 | 对我们方案的取舍 | 演示时必须核实 |
|---|---|---|
| 商品采集与选品数据 | 借鉴商品池、筛选、批次处理和导出，服务上文选品任务 | 销量、存货等字段来自公开展示、自有账户还是估算；规格、站点、采集时间、刷新频率及缺失值如何区分 |
| 1688 有货检测 | 借鉴图像匹配寻找候选货源，不把匹配结果当采购决定 | 同款判定、重量与采购成本依据、起订量、样品及交期核对；页面没有列明自动采购下单或付款能力 |
| 一键自建与跟卖 NSKU | 区分新建商品与对已有商品提交卖家报价两条路径 | 目录是否准确匹配、品牌及销售授权、字段补录与审核；批次中的成功、失败和待审核如何逐项反馈，不能将提交成功记成可售 |
| 自动定价与官方调价 | 借鉴确定性算价与批准范围内的价格维护，先查平台原有工具 | 采购、物流、平台、仓储、广告及退款损失哪些已计入、哪些为估算；费用缺项及利润底线如何处理，算法沿用经营口径文档 |
| 商品、订单与约仓管理 | 作为后续库存维护、订单跟进和入仓预约的复用候选 | 数据时效、FBN／ASN 实际适用流程、人工步骤、重复提交、超时及部分成功；预约不等于保证有仓位 |
| 教程权限、视频与后台 CMS | 不纳入当前产品范围，继续使用岗位指南和 SOP | 除非后续确有培训内容交付问题，否则不开发会员、课程、视频播放进度或 CMS |

要求供应商用同一份获准样例演示正常和失败情况，逐步标出哪些自动、哪些需要人工，能否导出结果或提供允许调用的接口。页面列有图片补全和 AI 找同款，但不能据此认定具有完整套图生成；也不能把未列出的广告管理或自动采购当作已支持。

我们的差异不在于把同样按钮再做一遍，而是将“发现问题／提出任务 → 有依据的方案 → 明确批准 → 调用已有能力 → 核对结果”串起来。能直接使用现成软件的环节先复用，没有合法稳定接口时再比较文件交换或必要的单点自动化。

### 参考瑞大师的任务体验与插件协同

2026-09-23 重新读取 [瑞大师首页](https://www.noonmaster.com/)。官网声明云端托管、FBN／FBP／NGS 刊登、任务进展与失败反馈等能力，并出现插件安装线索；尚未验证插件与服务端分工、关闭浏览器后的执行行为或对外 API。以下补充与 NOON ERP 对照中不同的重点，不把两家功能相加当作首期开发清单。

| 值得参考的能力 | 我们怎么吸收 | 演示与采用前核实 |
|---|---|---|
| 云端托管与批量任务反馈 | 每个商品分别显示进度、失败原因及待处理事项，不只给整批一个成功／失败结果 | 浏览器关闭后是否继续、任务取消是否生效、部分成功如何处理、失败和重试是否扣次数、如何避免重复刊登 |
| FBN／FBP／NGS 分模式刊登 | 共用商品事实，按站点、账户及实际模式选择步骤与字段 | 不同模式的可用账号、必填资料、人工补录、审核与可售状态；不从宣称支持推断所有组合可用 |
| 多来源采集与图片找同款 | 连接商品候选和货源核查，保留来源及人工确认结果 | 同款与相似款判定、规格差异、数据时效和素材使用权；不把匹配直接当采购结论 |
| 图文翻译与素材加工 | 既支持生成新素材，也支持对授权的已有素材做本地化 | 首页提到中文图片转英文，不能推断阿语图片能力已验证。去水印、去品牌或换模特不作为默认操作，不改变商品事实或制造误导 |
| 预约、NGS 文件及异常排查 | 任务不仅提交，还核对预约、文件、价格和库存是否实际生效 | 平台允许的操作方式与频率、超时及重复处理、何时停止；海关编码建议需人工核实，不等于完成清关或保证仓位 |
| 多店与经营统计 | 按实际权限查看店铺数据，执行前再次确认目标店铺和商品 | 角色权限粒度、跨店隔离、统计更新与利润口径；中文化界面不等于已解决授权或经营判断 |

插件负责当前页面的选择、预览和发起任务；后台保存任务并处理可独立执行的工作；工作台与飞书呈现同一结果和待处理项。这是我们拟议的分工，不是对瑞大师内部技术的认定。需要本地页面的步骤在浏览器关闭后应暂停，不能把“云端托管”理解为所有步骤都可脱离浏览器运行。

本次首页未明确说明供应商采购下单、付款、广告投放管理或开放 API，不能将其列为已支持。与前述 NOON ERP 一起用相同样例比较任务完成度、失败可追查性、计费及人工接手成本，不依据“几分钟完成”等营销话术决定。

### 主底座优先验证 Octop，不直接定案

| 事项 | [Octop](https://github.com/TencentCloud/Octop) | [DSH Desktop](https://github.com/anywhere-labs/dsh-desktop) |
|---|---|---|
| 更匹配的目标 | 常驻 Web＋飞书入口，逐步供部门使用 | 个人本机上的会话、Skills 和素材工作 |
| 已读到的实现 | Python/FastAPI、React、Web 用户管理、飞书收发、cron、Skills/MCP | Electron、React、插件、会话存储、Skills、MCP、本地任务通知 |
| 需要二开的界面 | 经营概览与业务任务页；未确认稳定的任意业务 UI 插件契约 | 运营插件页；不建议重写桌面壳或维护大量分叉 |
| 主动提醒 | 有定时与飞书发送基础，仍需持久发送记录、去重与补发 | 本轮只确认本地任务完成／失败通知；持久巡检及飞书接入需补 |
| 业务批准 | 默认 HITL 关闭、工具防护为 warn；IM 身份归 Agent owner；部分待批状态在内存 | 有工具批准实现，不等于店铺、金额、参数和时效上的业务批准 |
| 可靠执行 | cron 重载不等于执行队列恢复；cron 遇人工交互会报错 | 桌面退出、休眠后的持续任务未验证；不能用聊天历史替代业务任务记录 |
| 多人边界 | Web 隔离与 IM 身份不是同一回事，共享 Agent 写权限需特别限制 | 局域网开放缺少鉴权，不能直接作为部门共享后台 |
| 构建维护 | 有锁文件和公开核心源码包，但未实测独立构建，核心仓库维护入口待核 | 有内置 runtime 与哈希校验，但开发／打包链部分默认跟随 Agents Anywhere main，需固定输入 |
| 许可边界 | 根 MIT；内置四类办公 Skills 有不同限制条款，覆盖授权需先核实 | 根 MIT，抽样 runtime MIT；第三方依赖未完成全包审查 |

本轮读取的正式发布：Octop v1.0.1、DSH Desktop v2.0.13，GitHub 发布时间均为 2026-09-19（UTC）。DSH master 包版本、stable／beta runtime 与正式安装包并不完全一致，不能混用结论；试验应选择并记录一个明确版本。

**Octop 采用门槛：** 内置办公 Skills 的授权覆盖或合规替换有明确处理方案；固定版本能启动；身份、任务与提醒测试通过。未解决时不批准整包二开分发。核心 Harness 已在公开 PyPI sdist 中发现源码和 MIT，不应简单称为闭源，但完整依赖和构建仍未验证。

**DSH 的备选条件：** 若近期确定只做个人本机任务，可优先测试插件路线；若仍要求关机后提醒和多人访问，必须计入额外常驻服务与身份管理成本。它是独立社区项目，不是 DeepSeek 官方桌面客户端。

不同时深度二开两个底座。候选都不适合时，保留已验证的业务能力，以简单网页和任务服务实现必要入口，而不是强行套入某个 Agent 框架。

**外发和费用：** 主技能仓库称 API 目前免费、无需密钥，并说明条款可能改变；不能推成永久免费或开源后端。关税 Skill 会向 Accio 发商品描述及属性，数据留存与二次使用未核实；使用前确认 [服务条款](https://terms.accio.com/terms/b_end_product_protocol/20241108154829935/20241108154829935.html)、额度和外发范围，不提交未经批准的敏感资料。

**采用顺序：** 有采购或物流任务需求时，先核实实际技能文件、许可、目标国家与数据依据，再检查 Octop 工具调用适配，最后用同一份获准样例测试结果、缺失和失败处理。CBM、计费重量等确定性计算优先做普通业务工具供 Agent 调用，不必为每个计算建 Agent。只有完成这些验证才列入实施范围，不自动安装或持续轮询新仓库。
