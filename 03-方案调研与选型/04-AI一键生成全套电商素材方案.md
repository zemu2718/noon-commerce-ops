## 先说结论

这里的“一键”只指**一次提交商品资料，生成一批可审核的素材草稿**，不代表自动发布、自动上架、自动投放或自动通过平台审核。

当前建议：

1. 先用本机 `ecommerce-image-studio` 作为素材分工和提示词标准，拿少量已确认 SKU 做样例。
2. 优先参考 [Novaryns](https://github.com/usscottli-ctrl/novaryns) 的产品结构，但不要把它当作“可直接商用的纯开源方案”：仓库公开源码和 AGPL-3.0 只解决一部分代码使用问题，网络服务分发、修改版公开和商业 Pro 授权仍需按项目条款核实。它最接近“商品套图＋抠图换背景＋试衣＋创作画布”的综合工作台。
3. 图片和视频任务分开研究：[AI E-Commerce Media Studio](https://github.com/ronchen0927/AI-E-Commerce-Media-Studio) 重点看商品图处理、异步任务和图生视频；[ClipForge](https://github.com/xixihhhh/clipforge) 重点看脚本、配音、字幕和平台比例输出。
4. 服装、鞋、包等类目再研究 [OpenTryOn](https://github.com/tryonlabs/opentryon) 或 [OpenVTO](https://github.com/Prompt-Haus/OpenVTO)；商品目录、模特和素材库可以参考 [Retail Asset Creation](https://github.com/siddythings/retail-asset-creation)。
5. 暂不建设完整自研平台，也不先接 noon 生产写权限；先用结果证明能减少实际整理、修图和审核时间。

本篇是公开资料初筛和拟议试法，不代表已安装、购买、接入、试用或证明经营收益。noon 站点、账户能力、FBN／FBP、广告接口和实际费用仍需单独核实。

## 要生成什么

默认一套生成六类素材，按平台和商品类型调整：

| 素材 | 用途 | 基本要求 |
|---|---|---|
| 商品主图 | 商品页首图 | 商品清楚、背景干净、少装饰，不编造徽章或认证 |
| 生活方式图 | 展示使用场景 | 场景真实，不能把竞品或不属于商品的配件混入画面 |
| 广告首帧 | TikTok、Meta 等信息流 | 小尺寸仍看得清，保留文字安全区，不堆复杂文案 |
| 卖点图 | 解释一个商品特点 | 只写商品资料能证明的事实，避免医疗、性能和绝对化承诺 |
| 细节图 | 材质、结构、包装或工艺 | 放大后不改变颜色、纹理、Logo 和包装文字 |
| 市场变体 | 做 A/B 测试 | 只改变场景或表达方式，不改变商品本身和关键事实 |

服饰、包、珠宝、美妆工具等可穿戴商品，应至少包含一张佩戴、使用或模特场景图；这表示风格和使用方式，不承诺准确尺码或实际试穿效果。

## 当前 Skill 能做什么

本机已提供 `ecommerce-image-studio` Skill。它负责根据商品图、平台、市场和目标，规划素材角色、构图、场景、文字和复核边界；实际图片生成使用 `$gpt-image-2` 图像编辑流程。

可覆盖的方向包括：

- Amazon、Shopify／DTC、TikTok Shop、Meta、小红书、抖音、淘宝／天猫、Shopee、Temu 和 Etsy；
- 白底主图、高级棚拍、真实生活场景、UGC 风格、卖点图、材质特写、礼品场景和模特图；
- 单张商品图生成一套素材；不同素材各用专门提示词，避免把六个目标挤在一张图里。

需要提供至少一张商品参考图。生成时应尽量保留商品形状、比例、颜色、材质、Logo、包装、标签和 SKU 特征；参考图只能用于场景、光线、构图或氛围，不照搬竞品品牌、水印或完整广告版式。

Skill 的结果仍要人工检查：商品是否变形，文字是否正确，卖点是否有依据，是否出现多余配件、品牌或人物，是否符合目标平台尺寸和规则。复杂文字排版建议先生成干净底图，再用设计工具加精确文字。

## GitHub 候选比较

### 先明确要找的是什么

[美图设计室工具页](https://www.designkit.cn/tools) 不是工具导航站，而是一个在线电商视觉生产工作台。它把实际执行能力拆成六组：

- **商品图：** 商品套图、A+ 详情页、爆款图复刻、批量套图、AI 商品图、商品精修；
- **商品视频：** 爆款视频、视频复刻、视频背景移除、视频增强、视频翻译等；
- **自媒体创作：** AI 图文、文案和海报；
- **穿戴图：** AI 穿戴套图、AI 模特、AI 试衣、人物换背景、服装去皱、换色和 AI 试鞋；
- **图像处理：** 抠图、消除、变清晰、翻译、批处理、改尺寸、拼图和扩图；
- **智能工具：** PPT、证件照和 Logo 等通用创作。

因此，本轮候选不再按“有没有工具目录”筛选，而按能否提供下面这些**可执行的电商素材能力**筛选：

```text
商品图片或资料
→ 商品分析与保真处理
→ 套图／场景／模特／试衣生成
→ 局部编辑、抠图、换背景、翻译和改尺寸
→ 商品视频、配音和字幕
→ 批量任务、素材版本和结果下载
```

GitHub 上目前没有找到一个成熟开源项目完整覆盖这六组能力。下面的项目是按模块组合的候选，不是可以直接替代 designkit.cn 的现成产品。

以下判断来自仓库公开页面，未等同于实际可用性。许可证允许使用或修改代码，也不等于免费、没有模型费用、可以直接商用或已经适合生产。

### 最接近综合工作台

#### [Novaryns](https://github.com/usscottli-ctrl/novaryns)

- **定位：** 公开源码的电商 AI 商品视觉工作台，是目前最接近 designkit.cn 综合能力的候选；不能简单标为“可自由商用的开源替代品”。
- **覆盖：** 文生图／图生图、一键商品套图、抠图、背景生成、局部编辑、风格转换、去皱、虚拟试穿、服装平铺、3D 展示、印花提取、标题生成、模板库和 React Flow 创作画布。
- **技术与部署：** Next.js、TypeScript、Tailwind、PostgreSQL，支持 Docker Compose、本地媒体存储和可选 Cloudflare R2。
- **代码许可：** 仓库页面标注 AGPL-3.0。README 表示，修改后作为网络服务提供时需要按 AGPL 要求公开修改内容；同时列有闭源商业 Pro 授权和云托管收费选项。具体授权合同和适用边界尚未核实。
- **模型与第三方服务：** OpenAI Images API、Replicate；仓库 AGPL 不覆盖模型权重、API 服务、生成内容或第三方素材的许可。
- **成熟度与限制：** 公开源码可浏览，约 94 次提交、23 Stars、2 Forks，有 Docker、安装脚本和 CI，但没有公开 Release；早期项目，不能直接作为 noon 生产工具。
- **判断：** 可研究其产品结构和代码实现；若要对外提供修改版网络服务、闭源部署或商业化，先取得维护者书面许可并完成许可证审查。

#### [AI E-Commerce Media Studio](https://github.com/ronchen0927/AI-E-Commerce-Media-Studio)

- **定位：** 电商商品媒体生成后端，重点是商品图处理、图生视频和异步任务。
- **覆盖：** RMBG 抠图、自然语言商品图编辑、场景生成、GPT Vision 分镜、Wan 图生视频、FFmpeg 合成、API、任务状态和结果下载。
- **技术与部署：** Python、FastAPI、Celery、Redis、FFmpeg，支持 Docker 和 Google Cloud Run；本地模型可作部分云端能力的回退。
- **模型与许可：** OpenAI Vision、Replicate、RMBG-1.4、FireRed、Wan 2.2 I2V；MIT 许可证。
- **成熟度与限制：** 有测试、CI、Docker 和部署配置，但公开页面约 86 次提交、5 Stars、1 Fork；更像可运行的早期后端，不是完整前端工作台。
- **判断：** 重点参考商品图任务、视频任务、队列、状态和失败处理。

#### [Retail Asset Creation Platform](https://github.com/siddythings/retail-asset-creation)

- **定位：** 零售素材和商品资产工作台。
- **覆盖：** 模特生成、虚拟试衣、背景生成、背景移除、图片标签、商品目录和素材图库。
- **技术与部署：** Next.js、TypeScript、Tailwind、FastAPI、PostgreSQL、Redis；需要配置数据库、Redis 和多个模型服务。
- **模型与许可：** Leonardo.ai、Fashn.ai、OpenAI、Bria；MIT 许可证。
- **成熟度与限制：** 功能覆盖接近“商品目录＋模特／试衣＋素材库”，但实际效果依赖外部服务，不能据 README 推断生产稳定性。
- **判断：** 重点参考 SKU、商品事实、素材图库和模型能力如何分开管理。

#### [ClipForge](https://github.com/xixihhhh/clipforge)

- **定位：** 商品带货短视频生产工具，补足 designkit.cn 的“爆款视频”方向。
- **覆盖：** 商品卖点提取、脚本、钩子、CTA、AI 生图、图生视频、运镜、配音、字幕、SRT／WebVTT、卡拉 OK 字幕和多平台比例导出。
- **技术与部署：** Next.js、React、TypeScript、SQLite、Drizzle、FFmpeg、Docker，也提供 Electron 桌面打包。
- **模型与许可：** 多种图像／视频／TTS 服务，支持 Edge TTS；AGPL-3.0。
- **限制：** 需要按模型和配音服务配置 Key；生成和导出依赖外部服务与 FFmpeg；不包含自动发布到短视频平台。
- **判断：** 视频模块单独研究，不与首期商品套图混在一个试点里。

### 专业模块和本地方案参考

#### [OpenTryOn](https://github.com/tryonlabs/opentryon)

- **定位：** 试衣、服装处理和图像／视频生成工具包，不是完整的电商工作台。
- **覆盖：** 虚拟试衣、服装预处理、背景移除、图片编辑、图片／视频生成，并提供 Python API、CLI、MCP、OpenAPI 和 Next.js Studio。
- **模型与许可：** 支持或接入 FLUX、Vertex、FASHN、Qwen、GPT Image、Veo、Sora、Kling、Wan 等；Creative Commons BY-NC 4.0，商业使用不能直接假设允许。
- **判断：** 服装、鞋、包等类目再研究，先核实具体模型和数据的商业授权。

#### [OpenVTO](https://github.com/Prompt-Haus/OpenVTO)

- **定位：** 专注虚拟试衣、模特和试穿动画的 API／SDK 项目。
- **覆盖：** 服装替换、模特生成、试穿图和短动画试穿视频；提供 Python SDK、FastAPI 和 Playground。
- **许可与边界：** 页面标注 MIT，但模型、权重和外部服务仍需分别核实；不包含完整商品套图、详情页或通用图片处理。
- **判断：** 只在服饰类目需要上身展示时作为专项能力候选。

#### [xiaoqahax-ui/comfyui-ecommerce-workflows](https://github.com/xiaoqahax-ui/comfyui-ecommerce-workflows)

基于 ComfyUI，覆盖背景替换、场景图、AI 模特试穿、详情页、Banner 和批量 SKU；依赖 ComfyUI、SDXL 或 Flux、ControlNet、IP-Adapter、Inpainting 等节点和模型；Apache 2.0 许可证。

优点是可本地控制资料和模型，缺点是安装、GPU、模型和节点维护成本高，仓库公开维护信号较弱。只有在云端外发或长期费用确实成为问题时再研究。

#### [backblaze-b2-samples/ai-product-photo-studio](https://github.com/backblaze-b2-samples/ai-product-photo-studio)

围绕 SKU 管理商品参考图、历史素材、多角度、季节和生活方式变体，并将图片存入 Backblaze B2，附带 SHA-256 provenance manifest；Next.js、FastAPI、Python，MIT 许可证。

适合参考“生成＋素材库＋历史记录”的实现，不是完整 listing 或广告系统；依赖 OpenAI、Genblaze 和 B2，需计算生成和存储费用。

#### [context-dot-dev/ad-maker](https://github.com/context-dot-dev/ad-maker)

输入公开网站，提取品牌风格和 1—3 个商品，生成约 4—6 张品牌广告图；MIT 许可证。适合品牌广告创意原型，不适合多 SKU、平台多尺寸和完整商品页素材，且依赖 Context.dev、Vercel AI Gateway 等外部服务。

### 暂不优先

- [Atlas Marketing Studio](https://github.com/AtlasCloudAI/atlas-marketing-studio)：适合 UGC、短剧情、配音和口型同步的视频广告，但依赖多个视频服务，部署和密钥治理较重，不是首期商品图工具。
- [crispy](https://github.com/xolarvill/crispy)：把商品、素材和 Shopify／Meta 表现数据连接起来，适合参考“生成—审核—投放—反馈”；AGPL-3.0，且单用户、本地存储和多 API 部署风险较高。
- [product-ai-listing-studio](https://github.com/pkp666/product-ai-listing-studio)：覆盖 listing、图片和视频准备，但公开维护信号较弱，实际平台发布仍依赖人工或浏览器插件。
- [motiful/product-shots](https://github.com/motiful/product-shots)：仍适合 Agent 化地规划 Amazon、A+、广告和社媒素材，但它主要是 Skills 工作流，不是像 designkit.cn 一样的综合在线工作台；可作流程和提示词参考，不作为主平台候选。
- [clawnify/OpenListingStudio](https://github.com/clawnify/OpenListingStudio)：适合 Amazon listing、A+ 和商品图，但平台范围较窄，noon 字段、规则和实际部署能力未核实。

本轮没有找到同时满足“许可证清楚、代码可复用、明确针对 noon、可直接覆盖商品图、视频、穿戴图、图像处理和内容创作”的成熟开源项目。Novaryns 虽然公开源码并标注 AGPL-3.0，但存在网络服务公开义务和商业 Pro 授权边界，当前应归为“公开源码／受许可证约束的候选”，不能作为无条件开源方案。更现实的方向是先以它研究综合工作台结构，再按商品图、视频、试衣和素材管理拆分验证。支持 Amazon、Shopify 或其他平台，不能推断支持 noon 的账户、站点、FBN／FBP 或广告后台。

## 统一比较和试用方法

### 先准备固定案例

选少量已确认 SKU，准备：

- 原始商品图和已确认的商品事实；
- 商品颜色、材质、尺寸、包装、Logo 和可公开卖点；
- 目标平台、市场、语言和素材数量；
- 一套人工认可的正确结果，作为对照；
- 不含密码、密钥、客户资料和未批准经营数据的脱敏资料。

### 生成、审核、保存

```text
确认 SKU 和商品事实
→ 提交一套素材草稿任务
→ 逐图检查商品保真、事实、尺寸、文字和品牌风险
→ 人工批准、修改或单独重做失败项
→ 保存输入版本、能力版本、任务 ID、结果和费用
→ 再决定是否交给上架或投放流程
```

生成任务至少记录：批次、SKU、输入版本、能力或流程版本、外部任务 ID、尝试次数、状态、时间、结果、错误和证据链接。超时或结果不明时先查原任务，不直接重复提交；批量部分成功时只处理未完成项。

### 比较维度

| 维度 | 要看什么 |
|---|---|
| 商品保真 | 形状、比例、颜色、材质、Logo、包装、配件和文字是否正确 |
| 套图完整 | 六类素材是否都完成，风格、光线和商品表现是否一致 |
| 平台适配 | 尺寸、比例、文字安全区和主图限制是否满足目标平台 |
| 人工投入 | 生成前整理、等待、逐图检查、修改、返工和保存分别花多久 |
| 成本 | API、模型、存储、订阅、GPU、人工检查和维护费用是否齐全 |
| 数据边界 | 商品图和资料发往哪里，谁能看到，能否删除和导出 |
| 稳定性 | 失败、超时、断线、重启、重复提交和部分成功是否可追查 |
| 可维护性 | 版本、依赖、升级、退出和恢复人工流程是否清楚 |

模拟案例只能证明流程能运行，不能证明带来销售或利润。收益按 [经营目标和怎么算](../01-业务调研/02-经营目标和怎么算.md) 计算，不能把省下的生成时间直接称为净利润，也不能把销售变化直接归因于工具。

## 针对 noon 的试点顺序

### 第一步：只做素材草稿

使用已确认 SKU 和授权实拍，生成主图、生活方式图、卖点图、细节图和一个广告首帧；先选图片或视频其中一种，不同时扩展。只保存到指定目录，不自动上传、上架或投放。

通过条件：商品事实和视觉细节没有关键错误；六类素材的人工复核时间可记录；费用在预定上限内；失败和重复任务能识别；阿拉伯文或英文文字由人工检查。

### 第二步：比较批量能力

如果第一步证明有价值，再用 3—10 个 SKU 比较 Novaryns 的综合套图能力与 AI E-Commerce Media Studio 的图片任务能力，检查批量替换、尺寸、风格一致性、部分失败和断点续跑。服装类目另取样比较 OpenTryOn 或 OpenVTO 的上身图。不要因为批量方便就放开生产写权限。

### 第三步：决定是否增加视频和素材库

图片流程稳定后，再单独试 ClipForge 的商品视频，以及 Retail Asset Creation 的商品目录、模特和素材库管理。视频的模型费、配音费、FFmpeg 处理和人工复核要单独核算，不与图片套图混算。

### 第四步：决定是否本地化

只有当资料外发、持续模型费用或批量速度成为明确问题时，再评估 ComfyUI 或自建素材库。此时要把模型、节点、GPU、升级、备份、权限和退出成本一起计算。

### 第五步：有投放数据后再做反馈

积累稳定的素材版本和投放数据后，才考虑参考 `crispy` 关联素材、渠道、花费、点击、转化、收入和利润。先做只读报表，不自动改预算、价格或投放状态。

## 停止条件和下一步

遇到以下情况，停止自动生成或转人工：

- 商品、包装、Logo、配件或关键文字被明显改错；
- 资料缺失却由模型猜测商品事实或卖点；
- 生成结果不明、任务超时或无法确认是否重复扣费；
- 资料外发范围、许可证、账号权限或费用无法确认；
- 人工检查和返工时间没有减少，反而增加；
- 需要绕过验证码、风控、权限或平台限制；
- 不能保存任务版本、失败原因和逐项结果。

下一步回到 [改进清单](../02-岗位流程与改进/04-改进清单.md) 记录实际样例、批准范围、费用、结果和继续／调整／停止决定。确认采用后，再把稳定步骤写入对应岗位 SOP，不把本篇公开调研直接当作执行授权。
